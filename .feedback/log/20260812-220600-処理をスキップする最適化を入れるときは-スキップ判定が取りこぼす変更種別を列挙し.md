# 処理をスキップする最適化を入れるときは、スキップ判定が取りこぼす変更種別を列挙して検証する(安全側は常に「実行する」)

根因: 指示欠陥。Stopフックの検査を「変更があるときだけ」に絞る最適化で、変更検出を find -type f の mtime にしたため、ファイル削除を検出できなかった(消えたファイルには mtime が無い)。削除はビルドを壊しうるのに検査が飛ぶ、という静かな退行。親ディレクトリの mtime も見ることで修正。スキップ最適化はデフォルトが「速いが不正確」に倒れやすいので、判定漏れの種別(削除・改名・権限変更など)を明示的に列挙して検証すること。
