# 読み取り専用の分類はコマンド名ではなく引数まで見て決める

全コマンド共通の前処理(壊れた transaction journal の回復)を、読み取り専用コマンドでは警告へ格下げする実装で、report を無条件に読み取り扱いにしていた。report --mark は .last-retro を transaction で書くため、格下げしたまま transaction() へ進み、atomic_write_text が既存の journal を上書きしてから unlink する。『内容を確認のうえ削除して再実行してください』と案内した当の記録を、ハーネス自身が黙って消す。既存テストは report --since だけを読み取り経路として検証しており、--mark 付きの本番の入力に触れていなかった。根因: 実行誤り
