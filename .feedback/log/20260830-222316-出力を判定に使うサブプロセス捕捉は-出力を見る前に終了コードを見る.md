# 出力を判定に使うサブプロセス捕捉は、出力を見る前に終了コードを見る

護欄テストで `MISSING=$(tpy - <<PY ... PY)` の出力を `assert_eq "" "$MISSING"` で判定していたが、終了コードを見ていなかった。Python が例外や git コマンド失敗で死ぬと出力が空になり、"問題なし" と同じ形になって緑で通る — 検査したはずの項目が丸ごと無検証になる。レビューで exit 42 を注入して再現。同じ穴が test_config.sh と test_plugin_manifest.sh の5箇所にもあり、特にフック定義の正規化比較は両側が死ぬと "" == "" で成立していた。"問題が無ければ無出力" という契約のコマンドは、成功と沈黙した失敗が区別できない。tests/test_python_boundary.sh に走査を追加して固定した。根因: 実行誤り
