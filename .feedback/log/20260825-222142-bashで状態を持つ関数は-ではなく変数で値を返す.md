# bashで状態を持つ関数は$(...)ではなく変数で値を返す

PR #13再レビュー対応。maven_check_id が既出IDを MAVEN_USED_IDS に記録して連番を付ける設計だったが、呼び出しが cid=$(maven_check_id ...) だったため subshell で記録が毎回捨てられ、slug が衝突する2モジュールが同じIDへ潰れた。テストで検出。同じ形の欠陥をこのPRで既に一度作っている(_harness_python_resolve の cache)。command substitution は subshell を作るという性質は既知なのに、値を返す関数を書くと反射的に $(...) を選んでしまう。状態を持つなら変数で返す。根因: 実行誤り
