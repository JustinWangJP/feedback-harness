# 境界の性質(改行・encoding)は経路ごとの場当たり処理でなく一箇所の契約として書き、走査テストで書き戻しを止める

PR #13レビュー。Python出力のCR除去を on_stop.sh と post_edit.sh にだけ足したため、同じ出力を eval する harness_load_config と --list-checks の経路は無防備という不整合が残った。CPython の sys.stdout は create_stdio() が newline='\n' を渡すため Windows でもCRを出さない(=場当たりの2箇所は死にコード)。修正: 2箇所を削除して「境界の出力はLFのみ」を lib.sh のコメントで契約化し、tests/test_python_boundary.sh が実際の出力にCRが無いことを検証、あわせて scripts/ 配下への CR 除去の再注入を走査で禁止する。根因: 実行誤り
