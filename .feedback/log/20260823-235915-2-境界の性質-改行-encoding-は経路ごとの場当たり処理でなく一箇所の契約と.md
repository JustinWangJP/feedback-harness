# 境界の性質(改行・encoding)は経路ごとの場当たり処理でなく一箇所の契約として書き、走査テストで書き戻しを止める

PR #13レビュー。Python出力のCR除去を on_stop.sh と post_edit.sh にだけ足したため、同じ出力を eval する harness_load_config(HARNESS_LOG_TAIL_LINES=40\r が tail -n 引数と算術に渡る)と --list-checks の経路が無防備という不整合が残った。修正: 境界の harness_python が Windows(MSYSTEM)でのみ stdout を tr -d '\r' に通し、終了ステータスは PIPESTATUS で保つ。フック側の自前CR除去は削除し、tests/test_python_boundary.sh が (1) 実出力にCRが無いこと (2) Python が CRLF を書いても境界が落とすこと (3) 正規化経路で終了ステータスが保たれること (4) hooks/ が自前でCRを落とさないこと を検証する。なお当初は「CPython の create_stdio() は newline='\n' を渡すので Windows でもCRは出ない」と判断して除去を外したが、Windows CI が実出力 true\r\n で否定した。修正方針を逆向きに取り直している。根因: 実行誤り
