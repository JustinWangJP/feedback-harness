# 配布物から呼ぶCLIの入口はbash経由に一本化し、.pyを直接実行させない

PR #13再レビュー。skills/ と docs/pointer_agents.md は bash .../feedback.sh へ移行したが agents/feedback-curator.md の3箇所(promote / add / list)だけ feedback_log.py 直接実行のまま残った。shebang(#!/usr/bin/env python3)+実行ビットがあるため Unix では動作し、python.exe しかない Git Bash でのみ env: python3: No such file or directory になる — つまりこのPRが対象とする環境でキュレーション経路が全滅していた。しかも該当行はこのPRで編集されている(automation_candidates 追記)のにコマンドだけ移行漏れした。既存の tests/test_skill_paths.sh は裸参照(CLAUDE_PLUGIN_ROOT 無し)だけを見ており、PLUGIN_ROOT 付きのこの形は元から検出できていなかった。対策: 移行に加え scripts/*.py の直接実行を走査で禁止。根因: 実行誤り
