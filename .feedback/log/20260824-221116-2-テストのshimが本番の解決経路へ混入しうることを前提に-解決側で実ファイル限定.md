# テストのshimが本番の解決経路へ混入しうることを前提に、解決側で実ファイル限定にする

PR #13再レビュー。command -v は export -f された shell function も解決する(実測: command -v python3 が関数を返す)。tests/assert.sh は python3 が無い環境で python3 の shim を export するため、実 Git Bash で HARNESS_PYTHON 未設定だと _harness_python_works python3 が shim に成功し、harness_python が本番の _harness_python_exec ではなく shim を呼ぶ。shim は / で始まる全引数を cygpath 変換するので、自分が追加した tests/test_python_boundary.sh の『自由テキストを変換しない』アサーションが本番コードに触れないまま通る状態だった。CI が緑なのは Windows 全ステップが HARNESS_PYTHON=python を渡していたため。対策: 各テストで unset -f して回るのではなく _harness_python_works を type -t == file に限定して解決側で断つ。根因: 実行誤り
